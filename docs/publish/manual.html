OS Monitor 상세 사용 설명서

Kubernetes 클러스터를 이루는 노드의 Linux 운영체제 상태를 한 화면에서 보고, 이상을 빨리 알아차리고, 앞으로의 자원 부족을 미리 대비하기 위한 설명서입니다. 운영자와 조회 사용자를 대상으로 합니다.

01제품 소개

OS Monitor는 클러스터 노드의 Base OS(Linux)를 지켜보는 모니터링 플랫폼입니다. CPU·메모리·디스크·네트워크·부하 같은 지표와 호스트 시스템 로그(systemd journal)를 함께 모아, 무엇이 언제 왜 나빠졌는지 한곳에서 확인할 수 있게 합니다.

  • 보는 것: 노드 운영체제의 상태입니다. 파드나 디플로이먼트 같은 Kubernetes 리소스 자체는 다루지 않습니다.
  • 새로 설치하는 에이전트가 없습니다: 이미 운영 중인 Prometheus(Node Exporter)와 Loki에서 데이터를 가져옵니다. 노드에 SSH로 접속하지도 않습니다.
  • 쓰는 방법: 웹 대시보드, 터미널 CLI, 정기 리포트(HTML·PDF·JSON), REST API 네 가지입니다.

02처음 시작하기

  1. 관리자에게 받은 대시보드 주소로 접속합니다. 형식은 https://<게이트웨이 주소>/osmonitoring/입니다.
  2. 로그인 화면에서 아이디와 비밀번호를 입력합니다. 계정은 관리자가 사용자 관리 화면에서 만들어 줍니다.
  3. 처음 로그인했다면 개인 설정 탭에서 비밀번호를 바로 바꿉니다. 비밀번호를 바꾸면 그 계정의 다른 로그인 세션은 모두 끊깁니다.
  4. 개요 탭의 "조치 필요 항목"부터 확인합니다. 비어 있으면 지금 손볼 일이 없다는 뜻입니다.
설치 직후 기본 관리자 계정(admin / password)은 반드시 바로 바꾸세요. 배포할 때 환경변수 ADMIN_USERNAME·ADMIN_PASSWORD로 처음부터 다른 값을 지정할 수도 있습니다.

오른쪽 위에서 자동 새로고침 주기를 고를 수 있습니다(10초 · 30초 · 1분 · 10분 · 안 함, 기본 1분). 고른 값은 브라우저에 저장됩니다. 화면은 OS의 라이트/다크 설정을 따라갑니다.

03화면별 사용법

위쪽 탭으로 화면을 옮깁니다. 계정 권한에 따라 일부 탭이 보이지 않을 수 있습니다.

개요

클러스터 전체 게이지와 성능 요약을 보여 줍니다. 아래쪽 "조치 필요 항목"에는 해결되지 않은 이벤트와 임계값을 넘은 노드가 최대 10개까지 나오고, 누르면 해당 화면으로 이동합니다.

노드

노드별 CPU·메모리·디스크·코어당 부하, OS 배포판과 커널 버전을 보여 줍니다. 노드를 고르면 시계열 그래프가 열립니다.

이벤트

임계값 초과로 생긴 위기 이벤트 목록입니다. 상세 화면에서 원인 진단, 관련 로그, 해결 방법, 공식 문서 링크를 볼 수 있습니다.

로그

노드의 시스템 로그를 우선순위·노드·서비스(unit)로 걸러 봅니다. 요약 카드와 "탐지된 패턴"(9가지 이상 징후) 표가 함께 나옵니다.

예측

앞으로 7·30·90일 뒤의 사용률 추정치와, 자원이 가득 찰 때까지 남은 일수를 보여 줍니다. 신뢰도 열을 꼭 함께 보세요.

리포트

일간·주간·월간·연간 리포트를 만들고, 미리 보고, 내려받습니다(HTML·PDF·JSON).

개인 설정

자기 비밀번호를 바꿉니다. 모든 사용자가 쓸 수 있습니다.

사용자 관리

관리자만 보입니다. 계정을 만들고, 역할(관리자·조회자)과 볼 수 있는 화면을 정합니다.

05이상 대응 흐름

  1. 알아차리기: 개요의 "조치 필요 항목"이나 이벤트 탭에서 critical·warning 표시를 확인합니다.
  2. 원인 보기: 이벤트 상세에서 진단 내용과, 같은 시간대의 해당 노드 시스템 로그를 봅니다.
  3. 로그로 확인하기: 로그 탭에서 노드와 시간대를 좁혀 OOM Kill, 디스크 I/O 오류 같은 패턴이 같이 나타났는지 확인합니다.
  4. 조치하기: 이벤트 상세에 나온 해결 방법과 공식 문서 링크를 따라 조치합니다.
  5. 재발 막기: 예측 탭에서 같은 자원이 다시 차오르는 추세인지 확인하고, 필요하면 용량을 늘리는 계획을 세웁니다.

06예측 읽는 법

예측은 하루 단위로 모은 최근 30일 사용률에 선형 회귀를 적용해 계산합니다. 매일 새벽에 다시 계산합니다. 데이터가 적어도 값은 보여 주지만, 신뢰도를 함께 표시합니다.

신뢰도데이터어떻게 쓰나
high30일 이상이거나, 14일 이상이면서 추세가 거의 평평함용량 계획의 근거로 써도 됩니다
medium14~29일방향은 믿을 만합니다. 날짜는 여유를 두고 봅니다
low3~13일참고만 합니다
very_low3일 미만현재값을 그대로 이어 붙인 수준입니다

"가득 찰 때까지 남은 일수"가 7일 이하이면 긴급(high), 그보다 길면 보통(medium) 권고로 표시됩니다.

07리포트

  • 자동 생성: 일간 리포트는 매일 01:00에 만들어집니다.
  • 직접 생성: 리포트 탭이나 CLI monitor report로 일간·주간·월간·연간 리포트를 만들 수 있습니다.
  • 형식: HTML(브라우저에서 바로 미리보기), PDF(보고·보관용), JSON(다른 시스템 연동용).
  • 내용: 노드별 평균·최대 사용률, 최대 대비 비율, 이벤트 요약.
2026년 7월 이전에 만든 리포트는 내용이 데이터베이스에 저장되지 않아 내려받을 수 없습니다. 같은 기간으로 다시 생성하세요.

08CLI 사용법

터미널에서 표 형태로 상태를 봅니다. 색으로 임계값을 구분합니다.

monitor status <클러스터>     # 클러스터 전체 요약
monitor nodes <클러스터>      # 노드별 OS·커널·CPU·메모리
monitor os-metrics            # 노드별 상세 지표 (좀비 프로세스, inode 포함)
monitor top                   # 사용량 상위 노드
monitor events                # 위기 이벤트 목록
monitor predict               # 예측 결과
monitor report                # 리포트 생성
monitor logs                  # 시스템 로그 조회와 이상 징후 탐지

09계정과 권한

역할할 수 있는 일
관리자모든 화면, 사용자 관리(계정 생성, 역할·화면 권한 지정)
조회자관리자가 허용한 화면만 볼 수 있습니다. 개인 설정은 항상 쓸 수 있고, 사용자 관리는 쓸 수 없습니다.

화면 권한은 메뉴를 숨기는 데서 끝나지 않습니다. 서버도 같은 규칙으로 요청을 확인합니다.

10보안 수칙

  • 기본 관리자 비밀번호는 설치하자마자 바꿉니다.
  • 시스템 로그에는 인증 기록처럼 개인정보가 들어 있을 수 있습니다. 로그 화면을 캡처해 공유할 때는 사용자 이름이나 IP를 가리세요.
  • DB 비밀번호 같은 비밀값은 Sealed Secrets로 암호화해서 Git에 보관합니다. 평문 값은 메신저나 문서에 붙여 넣지 않습니다.
  • OS Monitor는 노드에 SSH로 접속하지 않습니다. 수집을 위해 노드 계정이나 키를 줄 필요가 없습니다.

11문제 해결

로그인했는데 곧바로 다시 로그인 화면이 나옵니다.
세션이 만료됐거나, 다른 곳에서 비밀번호를 바꿔 세션이 끊긴 경우입니다. 다시 로그인하세요.
탭이 일부만 보입니다.
조회자 계정에 허용된 화면만 보입니다. 필요한 화면은 관리자에게 요청하세요.
노드 값이 비어 있습니다.
최근 10분 안에 수집된 데이터가 없다는 뜻입니다. 해당 노드의 Node Exporter가 동작하는지 관리자에게 확인을 요청하세요.
로그 탭에 아무것도 나오지 않습니다.
호스트 저널 수집기(promtail)가 그 노드에서 동작하지 않거나, 노드에 영구 저널(/var/log/journal)이 꺼져 있는 경우입니다.
예측 값이 현재값과 같습니다.
데이터가 3일 미만이라 추세를 계산할 수 없는 상태입니다(신뢰도 very_low). 며칠 지나면 자연스럽게 나아집니다.
알림이 어디에도 오지 않습니다.
알림 규칙은 평가되고 있지만, Alertmanager에 받을 곳(메일·메신저 등)이 아직 설정되지 않았습니다. 관리자에게 수신처 설정을 요청하세요.
